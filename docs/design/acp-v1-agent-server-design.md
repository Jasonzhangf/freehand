# ACP v1 Agent Server Design

## Decision

Expose Freehand as an Agent Client Protocol (ACP) v1 endpoint. The official
`agent-client-protocol` Rust SDK owns the wire schema, JSON-RPC framing, and
stdio transport. `freehand-acp` is a thin adapter that implements the SDK
`Agent` role and routes `session/prompt` to the Freehand runtime live-reason
turn mainline (`run_live_reason_turn`). The daemon hosts the adapter over
stdio via `freehand-daemon acp`. ADP remains the internal WebUI transport.

## Boundary

```text
ACP NDJSON / JSON-RPC 2.0
        |
        v
agent-client-protocol SDK  (wire, framing, transport, parameter validation)
        |
        v
freehand-acp  FreehandAgent::connect_to  (initialize / session/new /
        |                                  session/prompt / session/cancel)
        v
freehand-runtime  run_live_reason_turn  (master_work mainline; turns poll
                                        LiveReasonCancelToken mid-flight)
```

`freehand-acp` does not own framing, JSON-RPC errors, parameter validation,
or session persistence. The SDK enforces framing, initialize-before-methods,
and parameter schema before reaching the adapter. The adapter only:

- registers handlers for `initialize`, `session/new`, `session/prompt`;
- registers the `session/cancel` notification handler that flips the
  per-session cancel token;
- persists the session working directory on `session/new` and forwards it
  to `LiveReasonTurnRequest.cwd` on `session/prompt`;
- maps `session/prompt` to one `run_live_reason_turn` call on the tokio
  blocking pool, with the session cancel token attached;
- translates the runtime turn outcome into `StopReason::{EndTurn, Cancelled,
  Refusal}`. `RuntimeLiveBridgeError::Cancelled` maps to `StopReason::Cancelled`;
  every other runtime error maps to `StopReason::Refusal`.

The adapter never adds an ACP frame to ADP, never persists sessions, never
mirrors control state into business text.

## v1 Scope

Supported methods:

- `initialize`
- `session/new`
- `session/prompt`
- `session/cancel` (notification)

Explicitly out of scope for this slice:

- `authenticate`
- `session/load`
- `session/resume`
- `session/list`
- `session/close`
- `session/delete`

If a client sends any of the unsupported methods, the SDK returns a typed
JSON-RPC method-not-found error before the adapter is invoked. We do not
declare those capabilities in `agentCapabilities`; the wire and the
advertised capability set stay in lockstep.

Prompt content is restricted to ACP `text` blocks; image, audio, inline
embedded resources, resource links, MCP servers, filesystem proxy, terminal
proxy, permission requests, socket transport, and vendor extensions are
explicit unsupported errors or are advertised as unavailable.

## Cancel semantics

`session/cancel` is a fire-and-forget notification that flips the
per-session cancel token atomically. The token is the
`LiveReasonCancelToken` (an `Arc<AtomicBool>`) shared with
`run_live_reason_turn`; the runtime polls the token mid-flight and aborts
the turn with `RuntimeLiveBridgeError::Cancelled` when it sees the flip.

The adapter maps the cancelled runtime error to `StopReason::Cancelled` in
the `session/prompt` response. A successful in-flight turn returns
`StopReason::EndTurn`; any other runtime failure returns
`StopReason::Refusal`.

The token is reset after each turn returns (either by completing normally or
by aborting), so a stale cancel does not leak into the next prompt.

## Lifecycle

1. `initialize` precedes every other request; the SDK enforces this.
2. `session/new` allocates a transport-local session id, records the
   session working directory, and creates a fresh cancel token. The id is
   generated by the adapter; the Freehand runtime owns no ACP session
   persistence.
3. `session/prompt` loads the selected agent config (default `master`),
   builds a `LiveReasonTurnRequest` (with the stored session cwd), and
   runs one turn on the blocking pool. The runtime may abort the turn
   mid-flight when the cancel token flips.
4. `session/cancel` flips the cancel token. If a `session/prompt` is in
   flight, the runtime aborts it and the adapter returns `Cancelled`. If
   no prompt is in flight, the next prompt returns `Cancelled` immediately.
   Either way, after the turn returns the adapter resets the token so the
   following prompt is not cancelled.

## Error Contract

- Malformed NDJSON, malformed JSON-RPC, unknown methods, invalid params,
  and missing handshake are enforced by the SDK and surfaced as JSON-RPC
  error frames.
- Unknown ACP session on `session/prompt` returns a typed
  `invalid_params` JSON-RPC error from the adapter.
- Runtime turn failures surface as `StopReason::Refusal`. The adapter does
  not synthesize a successful turn from a failure.

## Verification

- `cargo test -p freehand-acp` covers the pure helpers (`extract_text`,
  `monotonic_id`, cancel token flip).
- daemon `acp` end-to-end smoke runs against the real binary over real
  stdio:
  - `initialize` returns the agent capability advertisement with only the
    methods we actually implement.
  - `session/new` returns a generated sessionId.
  - `session/prompt` returns `stopReason end_turn` through the real
    runtime live-reason turn mainline with the configured agent.
  - `session/cancel` followed by `session/prompt` returns
    `stopReason cancelled` without invoking the provider.
  stdout carries only NDJSON JSON-RPC frames; stderr stays clean.
